Como ler este documento

Texto riscado: item ja implementado ou confirmado no projeto.

Texto sem risco: item que ainda falta implementar, revisar ou corrigir.

Item parcial: possui uma parte pronta e outra parte pendente. As subtarefas mostram a divisao.

Resumo atual

O Plot ja possui uma base demonstravel: autenticacao, questionario de generos, recomendacoes por API, navegacao principal, perfil editavel e APK Android atualizado. A maior parte das pendencias vem de recursos anunciados nos slides antes de serem implementados.

  • Aplicativo Ionic e Angular estruturado e compilando.
  • APK Android atualizado em apk/app-debug.apk.
  • Suite automatizada executando com 9 testes aprovados.
  • Corrigir os 12 erros restantes do lint.
  • Alinhar README e slides com o escopo realmente entregue.

Requisitos funcionais

Autenticacao e conta

  • Cadastro de usuario com nome, e-mail e senha.
  • Login com e-mail e senha.
  • Login com conta Google.
    • Fluxo implementado para navegador com Firebase.
    • Validar e adaptar o fluxo para funcionamento confiavel dentro do APK Android.
  • Manutencao de sessao e redirecionamento automatico de usuario autenticado.
  • Logout do sistema.
    • Metodo de logout criado no servico de autenticacao.
    • Adicionar botao de sair na interface e redirecionar para a tela inicial.
  • Recuperacao de senha.
  • Protecao de rotas para impedir acesso direto ao feed, perfil e questionario sem login.

Preferencias e recomendacoes

  • Questionario com selecao de exatamente tres generos literarios.
  • Persistencia das preferencias do usuario no Firestore.
  • Feed personalizado com livros carregados conforme os generos escolhidos.
  • Consumo da API gratuita Open Library.
  • Exibicao de titulo, autor e capa quando fornecidos pela API.
  • Adicionar uma imagem padrao existente quando a API nao retornar capa.
  • Trocar ou mapear o genero "Classicos", pois a consulta atual nao retorna livros.
  • Exibir sinopse real dos livros.
  • Exibir avaliacoes reais ou remover as estrelas decorativas.
  • Implementar busca de livros por texto.
  • Implementar paginacao ou carregamento progressivo para listas maiores.

Navegacao e exploracao

  • Navegacao entre feed, explorar e perfil.
  • Pagina Explorar registrada nas rotas e carregando livros da API.
  • Pagina Explorar.
    • Lista inicial funcional usando livros de romance.
    • Adicionar filtros, busca ou escolha de genero para que a pagina seja realmente exploratoria.

Perfil

  • Perfil exibindo nome e e-mail do usuario autenticado.
  • Edicao do nome persistida no Firebase Authentication e no Firestore.
  • Selecao de foto salva localmente por usuario no aparelho.
  • Definir se o e-mail tambem podera ser alterado e implementar a atualizacao no Firebase.
  • Substituir os favoritos fixos exibidos no perfil por dados reais.

Favoritos e avaliacoes

  • Implementar botao para favoritar e desfavoritar livros.
  • Persistir favoritos por usuario no Firestore.
  • Listar favoritos reais no perfil.
  • Definir a fonte das avaliacoes agregadas ou remover esse requisito do slide.

Armazenamento e recursos nativos

  • Firebase Authentication configurado.
  • Firestore usado para preferencias e dados basicos do perfil.
  • Uso simples de armazenamento local para a foto do perfil.
  • Ionic Storage, Preferences e SQLite citados no slide nao estao implementados. Implementar somente se forem realmente necessarios ou remover do slide.
  • Filesystem com arquivos CSV e JSON citado no slide nao esta implementado. Implementar ou remover do slide.
  • Criar e incluir o modelo ER anunciado no slide, caso ele faca parte da entrega.
  • Vibracao com Capacitor Haptics.
    • Plugin instalado no projeto.
    • Usar o plugin em alguma interacao ou remover a afirmacao de uso.
  • Camera citada no slide nao esta instalada nem utilizada. Implementar ou apresentar como trabalho futuro.

Qualidade tecnica

  • Build web concluido com sucesso.
  • Build Android concluido com sucesso.
  • APK Android atualizado apos as correcoes.
  • Testes unitarios destravados: 9 testes aprovados.
  • Corrigir 12 erros de lint restantes: migrar injecoes antigas para inject() e remover ciclos de vida vazios.
  • Remover imports Ionic nao utilizados apontados como avisos durante o build.
  • Adicionar testes comportamentais para login, questionario, feed, perfil e edicao de perfil. Os testes atuais verificam principalmente a criacao dos componentes.
  • Trocar o identificador Android generico io.ionic.starter por um identificador definitivo do Plot.
  • Trocar o nome nativo generico plot-app por um nome final de exibicao.
  • Usar uma versao LTS do Node.js em vez da versao impar v25 usada localmente.

Correcoes necessarias no README e nos slides

  • Corrigir a codificacao do README: os acentos e emojis aparecem corrompidos em alguns leitores.
  • Atualizar o slide de resultados: busca, favoritos e avaliacoes ainda nao podem ser apresentados como recursos concluidos.
  • Atualizar o slide de requisitos ou separar claramente "implementado", "em desenvolvimento" e "trabalho futuro".
  • Corrigir a contradicao entre "consumo passivo de conteudo" e os recursos interativos anunciados, como perfil editavel e favoritos.
  • Corrigir a descricao da API: Open Library e gratuita e a integracao atual nao usa API key.
  • Nao afirmar uso de paginacao enquanto ela nao estiver implementada.
  • Nao afirmar uso de camera, SQLite, Preferences, Ionic Storage ou Filesystem enquanto esses recursos nao estiverem implementados.
  • Revisar a afirmacao de Firebase Hosting: o projeto usa Authentication e Firestore, mas nao ha evidencia de hospedagem configurada.
  • Atualizar a tela "Sobre o Plot", que ainda promete favoritos antes da implementacao do recurso.

Ordem recomendada de trabalho

  1. Fechar a demonstracao principal: logout na interface, capa padrao, ajuste de "Classicos" e protecao de rotas.
  2. Implementar o diferencial anunciado: busca e favoritos reais persistidos no Firestore.
  3. Decidir o escopo das avaliacoes: integrar uma fonte confiavel ou retirar esse item da apresentacao.
  4. Limpar a qualidade tecnica: lint, avisos do build e testes comportamentais.
  5. Atualizar a apresentacao: mostrar como concluido somente o que pode ser demonstrado no APK.
